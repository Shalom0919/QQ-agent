# token 直接减半（early-finish）

> **显示名**用卖点（token 直接减半），**插件 id / 目录名**用机制名（`early-finish`）。

**token 直接减半，而且不改她的任何说话方式。**

## 它解决什么

每次运行都要把**整份提示词重新发一遍**。实测一次约 26k 字符 ≈ **22k token**，而一次运行经常要调 LLM
**2~3 次** —— 其中**绝大多数运行的最后一轮，只是为了调一次 `finish`**：

```
批 1：send_message          ← 她要说的话，这里已经发出去了
批 2：finish                ← 只为"宣告结束"再烧 22k token，没有任何实际产出
```

**这个插件把那轮砍掉。**

## 实测效果

同一角色、连续运行的对比（`usage.calls` 统计）：

| | 平均调用轮数 | 1 轮完成占比 | 最常见的一档 | 平均 prompt |
|---|---|---|---|---|
| 装之前 | **1.74 轮/次** | 35% | **2 轮（56%）** | 37684 tok |
| 装之后 | **1.07 轮/次** | **93%** | **1 轮（93%）** | 23728 tok |

- **折算成本降约四成**（按缓存 1/10 价计算：15879 → 9365 当量）
- **最常见的那一档直接从 2 轮变 1 轮 —— 单次减半**
- **对她的说话方式零影响**：它不碰提示词、不改人设、不拦发言，纯粹是调度优化

## 它什么时候**不**收尾（很重要）

为了不打断角色做事，只有**同时满足**这些条件才提前结束：

1. 这一批**真的把消息发出去了**（没有发送动作、或发送未确认 → 不收尾）
2. **没有工具失败**（有失败就保留正常循环，让她补救）
3. **没有"预告式结尾"**（说了"我去看看""等下告诉你"→ 保留循环，她下一批该有后续）
4. **没有"预告要交东西却没交"**（说了"给你发张图"却没发图 → 保留循环）

**任何异常一律按"不收尾"处理** —— 省 token 不值得拿流程冒险。

## 设置

| 设置 | 默认 | 说明 |
|---|---|---|
| 启用提前收尾 | 开 | 关掉就恢复原样（每次运行跑满所有轮次） |
| 试运行（只记录、不真的收尾） | 关 | 打开后只在日志写"本来会收尾"，不影响实际流程 —— 想先观察它什么时候生效就用这个 |


## 1.2.0 新增：提前收尾时，结束说明是"她的想法"（2026-10-06）

**问题**：她**自己**调 `finish` 时，控制台那行是**她自己写的理由**；但只要是被本插件**替她收的尾**，
那行就变成一句死话 —— `本地收尾策略判定：本批已交付完毕`，看起来像"这次没有思考过程"。

**现在**：插件会**从她这一轮的思考里抽一句"她打算怎么说"**当结束说明。比如原来是死话，现在会显示成：

> 两条：["去吧，多吃点","明天太阳落山，我等你"]——嗯，这个挺好…

**✅ 只装插件就能用，不需要改宿主。**
思考是通过核心的 `after-response` 钩子拿到的（那个钩子的载荷里带着 response，里面就有 reasoning），
而它**跑在早收尾判定之前**，所以插件自己就能取到。
如果你的宿主已经主动把 reasoning 递进了 `reply.local-policy`，插件会**优先用宿主给的那份**。

**为什么它不花钱**：她的思考**本来就在这一轮里生成了**，抽一句话是纯本地字符串处理，
**不需要再调一次 LLM** —— 所以**省 token 的原有效果一点没动**。

**什么情况下看不到**：她的思考本身就是空的（模型不支持思考 / 关掉了思考）。
那种情况会退回原来的说明 —— 没人能凭空造出她的思路，插件也不会因此报错。

## 和其它功能的关系

- **和"记心绪/写日记"类插件配合时注意**：如果角色习惯"发完话的**下一批**再记心绪"，
  提前收尾会把那一批掐掉。**建议在角色卡里要求"发消息和记心绪放在同一批工具调用里"**
  （绝大多数模型本来就会这么做，同批做的话两者完全不冲突）。
- 它**只**做"提前收尾"一件事。发言质量的检查（别解说自己、别反复催、别语气硬…）是另一个插件的事。

## 兼容性

- 依赖宿主提供的 `reply.local-policy` 能力口（`orchestrator` 的批次收尾判定点）。
- 宿主没提供这个口子时，插件加载正常、只是不生效，不会报错。
- **同一个能力只应由一个插件提供**：如果你还装了别的"提前收尾"类插件，请只留一个，
  否则谁生效取决于加载顺序。
