# 梗鲸表情包（whale-memes）

> **这个技能在 QQ Agent 控制台的「技能」页签里显示为一张绿色「生效中」卡片。**
> 装进 `skills/whale-memes/` 即生效，热重载会自动加载，不需要重启或刷新。

让机器人从「[梗鲸](https://aigengtu.com)」（aigengtu.com）里挑一张贴当下气氛的表情包，直接发到当前会话。

图库里是**蓝色大肥鱼（DeepSeek 鲸娘）**和各路 AI 娘化的梗图——正好和机器人自带的「小鲸鱼」人设同源，配起来不会串味。共 **1429 张**，持续更新。

**免 Key、免配置、免代理。** 图库是一份纯静态 JSON，没有任何鉴权。

---

## 它凭什么算「技能」而不是「插件」

这个项目里扩展分两型，判据只有一句话（见 README「扩展」一节）：

> **规则能写死 → 插件（`plugins/`）；要理解人话 → 技能（`skills/`）。**

本技能的所有关键判断都落在这句话的右边：

| 判断 | 能写死吗 | 所以 |
|---|---|---|
| 我这句话是什么语气？ | 不能，要读语义 | 交给模型 |
| 现在该不该配一张图？ | 不能，要看语境（对方在认真问事时就不该发） | 交给模型 |
| 哪张最贴这个气氛？ | 不能，1429 张没有规则可穷举 | 交给模型 |

插件只能提供 `providers` / `hooks`，**核心代码按能力名取用，模型根本看不见**——那样做出来的东西在群里就是"没反应"。所以这里用 `api.registerTool()` 把工具交给模型自己决定何时调用。

反过来，技能内部那些**能写死的事就写死**，不麻烦模型：图库索引缓存、语气词同义扩展、下载校验、会话去重、发送额度。分工是这个技能的设计核心。

## 什么时候会发图

只有两种情况，都由模型判断：

1. **主动配图** —— 机器人自己那句话有明显情绪、配一张正好替它把话说完（吐槽、委屈、得意、无语、被催更…）。它会自己克制：对方在认真问事、话题正紧、刚发过图，就不发。
2. **群友点图** —— 有人直接要（「来张表情包」「发个表情」「点一张」「来张气鼓鼓的」）。
   - 想先看看再挑：模型先用 `list_memes` 列出带编号的候选，对方点了哪张，再用 `send_meme` 的 `pick` 把那张编号发出去。

## 两个工具

| 工具（模型看到的完整名字） | 作用 |
|---|---|
| `whale-memes__send_meme` | 挑一张并**直接发出去**（一步到位，不用再调别的发送工具）。参数：`keyword` 语气词 / `character` 角色 / `pick` 指定编号 / `count` 张数 |
| `whale-memes__list_memes` | **只列候选、不发送**。不带参数则返回图库概览（有哪些角色、各多少张）+ 随机样例 |

> 工具 id 会被加载器自动加 `技能id__` 前缀，所以模型看到的是上面这种完整名字。

## 设置项

在技能卡片上点**齿轮**打开。10 项，改完即时生效：

| 设置 | 默认 | 说明 |
|---|---|---|
| 启用梗鲸表情包 | 开 | 关掉后两个工具和提示词片段**同时**失效 |
| 允许主动配图 | 开 | 关掉后只有群友明确要图时才发 |
| 默认角色 | `auto` | 主动配图时优先从哪个角色挑；`auto` = 按语气自己决定 |
| 一次最多发几张 | 1 | 1~3，防刷屏 |
| 每个会话每小时最多几张 | 6 | 按会话单独计算 |
| 每个会话每天最多几张 | 30 | 按会话单独计算 |
| 同一会话不重发同一张 | 开 | 会一直去重到图库里可选项用完，然后才允许复用 |
| 优先发原图 | 开 | 关掉则发缩略图（省流量、更快，清晰度低些） |
| 清晰度下限（短边像素） | 200 | 是**优先级**不是硬门槛——都不达标时照发，绝不空手 |
| 图库索引缓存时长（小时） | 12 | 索引约 530KB，缓存到本地避免每次拉；设 0 = 不主动刷新 |

## 它是怎么工作的

```
模型判断该发图
      ↓
取图库索引  ── 内存缓存 → 网络刷新 → 磁盘缓存（逐级降级，离线也能发）
      ↓
语气词 → 同义扩展 → 全库打分 → 同分会随机 → 剔掉本会话发过的
      ↓
逐张下载 → 认魔数验真图 → 量尺寸 → 落盘 → 发本地文件
      ↓
记账（会话去重 + 额度）
```

几个值得说的细节：

**① 中文没法靠分词命中。** 「生气」和图上写的「气鼓鼓」一个字都不一样。所以按**情绪分组**做了一次同义扩展（15 组，如 `委屈: 委屈/哭/泪/呜呜/可怜/惨`），让"语气词"能真的找到贴切的图。打分时按梗名（`『』` 里的文字）权重最高、图名次之、故事说明最低。

**② 必须"下载下来自己看"再发。** 实测这个图床在图不存在时返回的是 **`404 + text/html`（27KB 的 HTML 错误页）**，不是空图、也不是图片格式。只把 URL 甩给协议端的话，群里看到的是裂图，而我们连"失败了"都不知道。所以统一：**下载 → 认魔数 → 量尺寸 → 落盘 → 发本地文件**。

**③ 发本地路径而不是 URL。** `ctx.sender.sendImage(chatKey, { file })` 传本地路径时，协议端自己读磁盘，HTTP body 只有百来字节；传 base64 会让几 MB 走 HTTP 而超时。

**④ 逐张试、不空手。** 图床直链的死活事先看不出来（更像是"图没了"而不是"链接错了"），所以边试边收：原图不达标就看缩略图，都不行也照发一张，绝不让用户空手而归。

**⑤ 多图也能很快。** 带 `count` 时可一次发 2~3 张，会按"短边优先"排序挑大的。

## 数据落在哪

全部在数据目录下，**不在技能目录里**（技能目录是只读的代码）：

```
data/whale-memes/
  ├── catalog.json   图库索引缓存（约 380KB，离线可用）
  ├── state.json     每个会话发过什么（去重的依据，最多留 500 条）
  └── tmp/           下载下来的临时图，48 小时自动清理，可整个删掉
```

想**清空去重记录**（让机器人在某个群里可以重新发之前发过的图）：删掉 `state.json` 即可，下次会自动重建。
想**强制刷新图库**（站点更新了新图）：删掉 `catalog.json`，或把"缓存时长"改成 0 再改回来。

## 排错

| 现象 | 原因与处理 |
|---|---|
| 技能页显示**红色「加载失败」**，鼠标悬停有原因 | 把原因原样复制出来即可定位。本技能已用项目自带的清单校验器验证过，`problems` 为空 |
| 显示**黄色「依赖未就绪」** | 本技能 `requires` 为空，正常不会出现；若出现说明 `permissions` 被改坏了（必须是 `["web_fetch"]`） |
| 卡片存在但**灰色「已关闭」** | 点卡片开启。这是唯一的总开关 |
| 群里**完全不发图** | 先看「响应档位」——档位太低时普通消息根本不会触发模型；再确认卡片是绿色「生效中」 |
| **发出去是裂图** | 不该发生（有魔数校验兜底）。若真出现，多半是协议端与程序不同机，本地路径读不到 → 会在日志里看到"改 base64 发送" |
| 提示**"图库这会儿连不上"** | 站点暂时不可达，且本地没有缓存。等一会儿再说，不影响其它功能 |
| 同一张图反复发 | 检查「同一会话不重发同一张」是否被关掉；或该会话额度内的可选项已用完（会明确提示"重复使用"） |

排查用日志：`data/logs/qq-agent-YYYY-MM-DD.log` 里搜 `whale-memes`，加载与每次发图都有记录。

## 文件构成

```
skills/whale-memes/
  ├── skill.json   清单（id / 权限 / 设置声明 / 提示词片段）—— 加载器读它
  ├── index.js     入口（注册两个工具 + 导出 promptSections）—— 加载器读它
  └── SKILL.md     本说明文档（给你和以后的 AI 助手看，程序不解析）
```

> `SKILL.md` 与 `README.md` 都**不参与加载**。QQ Agent 的加载器只认 `skill.json`（或 `plugin.json`）与入口 `index.js`。改这个文件不会影响技能行为。
